# B-001: "Cancelled" over-selection message shown, but erase still happens

- **Status**: Fixed — the over-selection guard (including its message and
  residual delete) was removed entirely; erase-by-scribble always deletes
  the full selection now. See DECISIONS.md 2026-07-11 and CHANGES.md
  "Unreleased".
- **Symptom**: User scribbles to erase; the host shows "Scribble would erase
  too much nearby content — cancelled." (the over-selection guard message),
  but content is still visibly erased afterward.
- **Hypothesis**: Not a control-flow fallthrough — verified by reading
  `src/logic/erase.ts:140-167` directly. When the over-selection guard trips
  (`over > MAX_COLLATERAL_STROKES`, erase.ts:145), the big union-box
  `deleteLassoElements()` at erase.ts:167 is genuinely skipped via the
  `return` at erase.ts:164. **But** the abort branch itself
  (erase.ts:152-160) performs a *second*, smaller, intentional delete: it
  re-lassos just the scribble's own bounding box and deletes whatever that
  lasso selects, "to avoid leaving the scribble scrawl on the page" (comment
  at erase.ts:148-151). Per that same comment, this can also delete other
  strokes that happen to lie fully inside the scribble's own tiny bbox — not
  just the scribble mark itself. The message text says "cancelled" with no
  disclosure that a smaller delete still runs, so what the user sees (message
  says cancelled, then stuff disappears anyway) is consistent with the code
  *working as written* — the bug, if any, is the message being misleading
  about what "cancelled" means, not a logic fallthrough.
- **Evidence**: `src/logic/erase.ts:140-167` (guard condition, message
  assignment, residual scribble-box delete, early `return`).
- **Instrumentation**: None added yet — this is a static-read hypothesis,
  not yet confirmed on-device.
- **Next step**: Get user confirmation of which strokes actually disappear
  in a repro: exactly the scribble mark, or other content near it too. If
  needed, add a `dlog` at erase.ts:159 logging `ssel.result.length` (count of
  the residual delete) and compare against what's visually erased, to
  confirm the residual-delete hypothesis on device rather than a deeper
  control-flow issue.
